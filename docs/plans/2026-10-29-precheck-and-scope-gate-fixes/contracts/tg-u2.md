## Objective
Stop `hooks/scripts/writer-scope-gate.sh` from blocking a lead-programmer over files its dispatch lists, without
loosening it for files the dispatch does not list. spec-master reproduced the blocks offline on the real
transcripts (rfp-u1, label-ui, rfp-u2e). Plan section "Bug 2" gives the evidence for two root causes, both in
how the gate builds its listed set from the dispatch's first user message (the *dispatch message*):

- **R1.** The message's `## Affected files` names paths as bare bullets (`- tests/x.test.sh (new, mode 755): …`).
  `us_entries` keeps only backticked tokens, so the listed set is empty.
- **R2.** The message's `## Affected files` is prose that points at the unit's contract file and backticks
  some other token (`.claude/`). The listed set is then non-empty, so the contract fallback never runs, and
  the files the contract lists are blocked.

The fix stays inside the gate script and leaves `hooks/scripts/lib/unit-scope.sh` alone:
1. A bullet's first word in the message's own `## Affected files` is listed when it looks like a path.
2. When the message cites its **own unit's** contract file (`…/contracts/<Unit id>.md`), that contract's
   entries and `## Do NOT touch` exclusions are always added.

A contract cited for another unit still counts only when nothing is listed, as today. A file that neither
list names is still blocked. This unit runs `node bin/cli.js --update` for the gate, which regenerates
`.claude/hooks/scripts/writer-scope-gate.sh` and the config's `fileHashes`. `.claude/bin/review-precheck.sh` is
already current: tg-u1's fix round (`contracts/tg-u1-fix1.md`, after its FAIL 1) regenerated it, so `--update`
leaves it alone here. `hooks/scripts/` is not a version-stamped path, so there is no
version bump (constitution P3; plan Open Question 2).
