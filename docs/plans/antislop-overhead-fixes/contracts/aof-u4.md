Unit: aof-u4

## Objective
Knowledge files change only inside unit scope, and scribe runs once per plan instead of once per unit. When
`knowledgeWrites` is absent or `scoped`, scribe and spec-master write `CONTEXT.md`,
`docs/harness-glossary.md`, `README.md` and `docs/adr/*` only when that path is in unit scope: the dispatch's
`## Affected files`, a scribe dispatch contract's own edits, or a path the user's request names. Every other
knowledge change becomes a `Knowledge proposals:` report entry, which the orchestrator relays to the user.

Changes:
- `knowledgeWrites: "apply"` restores direct edits;
- an absent key or an unrecognised value resolves to `scoped`;
- a new `--update --knowledge-writes=<scoped|apply>` option sets the key, and this repo opts into `apply`
  through it;
- the orchestrator dispatches scribe once, after the last unit's PASS, carrying every unit's inputs, and skips
  it when there is nothing to close or write.

This is spec Step 4 (P3 alt 3B plus P4 alt 4B; operator ruling OQ1 = a).
