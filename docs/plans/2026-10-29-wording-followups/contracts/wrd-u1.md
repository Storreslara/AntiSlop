## Objective
Make `bin/review-precheck.sh` fail a multi-part stdout spec whose last part is empty, whatever the output. Today the spec `0` then (an empty part) passes on output `0\n\n`, because the compare drops exactly one trailing newline; a reader of the contract cannot see that reading, so the script now refuses the spec with `criterion <n>: fail stdout spec ends in an empty part`. An empty part before the last one still stands for a blank line. Also reword the comment at `run_one` that calls the `.` capture trick a "sentinel" (the harness term "WIP sentinel" is unrelated): the new comment uses no noun for it. Add two test cases, regenerate the installed copy and the config `fileHashes`, and commit them together.
