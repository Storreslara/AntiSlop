Unit: lp-vsr

## Objective
Switch version-stamp discipline from per commit to per release (plan decision D3). `hooks/scripts/version-stamp-check.sh` checks only two things, for every commit in the range that changes the `version` in `.claude-plugin/plugin.json`: (1) that same commit adds a `CHANGELOG.md` line naming the new version, and (2) the new version is not lower than its parent's. A commit that touches `agents/*.md` or `templates/*` without a bump is now `ok`. Constitution P3 is rewritten to match and set to `Version: 1.2.0` with an amendment-log line. The skill and the persona prose (lead-programmer, reviewer, scribe) say "per release". This unit is itself a release: it bumps to 0.31.227 under the OLD rule, so land the content change, the bump and the CHANGELOG entry in ONE commit.

## Retrieval
Fast path, no tracker issue. Spec: `docs/plans/2026-10-30-lean-pipeline.md`, section "U1 lp-vsr", decision D3, Constitution check P3. This file is the contract of record. First unit of the plan; nothing precedes it. Implementer tier: sonnet.

## Ordered edits
1. `hooks/scripts/version-stamp-check.sh`: iterate every commit in the range (`git rev-list`). For each commit whose `version_at "$c^"` differs from `version_at "$c"`: if `changelog_adds_version "$c" "$cnew"` fails, violation with offender `<short>:CHANGELOG.md`; if the new version is lower than the old (numeric compare of dotted integers, in the existing python3), violation with offender `<short>:.claude-plugin/plugin.json`. Remove the "touching commit with unchanged version" violation and the final endpoint `old = new` violation. Keep the output line format byte-for-byte: `version-stamp-check: <ok|violation|unknown> touched: <yes|no|-> old: <ver|-> new: <ver|-> offenders: <list|->`. `touched:` stays informational (does any commit in the range touch `agents/*.md` or `templates/*`). The early `touched: no` exit must no longer skip the bump checks: a bump-only commit is checked too. Rewrite the header comment to describe per-release semantics.
2. `tests/version-stamp-check.test.sh`: flip the existing "touched, no bump" cases (agents and templates) to expect `ok`. Add cases: (i) stamped-file commit without bump -> `ok`; (ii) bump commit with no CHANGELOG line naming the version -> `violation`; (iii) version decrease (with a CHANGELOG line) -> `violation`; (iv) bump-only commit (plugin.json only, no agents/templates, no CHANGELOG line) -> `violation`.
3. `tests/validate.sh`: reword the label to say a version bump needs its CHANGELOG line and never decreases. No other line.
4. `.claude/constitution.md`: rewrite P3 per D3 (a release is one commit that bumps the version and adds its CHANGELOG entry; content commits need no bump; the version never decreases; the `--update` fast path sees content at releases; checked by the script above). Header becomes `Version: 1.2.0 | Ratified: 2026-07-14 | Last amended: 2026-10-30`. Append `- 1.2.0 (2026-10-30): P3 changed to per-release semantics (lp-vsr).` to the amendment log. The text must contain the phrase `per release`.
5. `skills/version-stamp-discipline/SKILL.md`: description and body say the rule is per release; describe the two checks and what `ok`/`violation`/`unknown` mean now. Must contain `per release`.
6. `agents/lead-programmer.md` and `agents/scribe.md`: the version-stamp paragraph says content commits need no bump per release; run the script when the range contains a bumping commit; `violation` now means a bump lacks its CHANGELOG line or lowers the version. Both must contain `per release`.
7. `agents/reviewer.md`: the on-demand bullet says `ok` clears the per-release rule (bump has its CHANGELOG line, version never decreases).
8. Bump `.claude-plugin/plugin.json` and `package.json` to `0.31.227`; add one bold bullet under `## [Unreleased]` in the existing style ending `(lp-vsr, 0.31.227).`, describing the change. The `## [x.y.z]` heading form starts at the 0.32.0 release (U13), not here.
9. Run `node bin/cli.js --update --force-render` and commit the regenerated `.claude/` files with everything else in the same single commit.
